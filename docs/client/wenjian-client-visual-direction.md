# 问剑江湖客户端视觉方向设计

## 1. 文档目标

本文档基于首批概念美术素材，明确《问剑江湖》Unity 客户端第一阶段的视觉方向、角色比例、场景尺度、技能特效、HUD 氛围和工程约束。

本阶段目标是形成可执行的视觉基准，不把概念图直接当作最终资源。

### 1.1 2026-05-20 美术方向修订

首批概念图完成后，用户反馈不满意。项目经理与美术总监复盘后确认，下一轮美术方向从“生成好看的武侠概念图”调整为“定义可执行的游戏美术标准”。

用户确认的方向为：明快清爽的像素武侠，类似轻量动作肉鸽，战斗读得很清楚。

新的三条硬标准：

- 风格：清晰像素风，不要写实厚涂伪像素。
- 气质：明快、古朴、有剑意，不要过暗、过脏、过西幻。
- 用途：每张图都必须服务游戏落地，比如角色尺寸、地块规格、战斗可读性、UI 信息层级。

第二轮素材不再直接沿用首批提示词，而是围绕角色规格、战斗场景、HUD、技能特效、敌人剪影、主城地块和秘境房间建立可执行基准。详细标准见 `docs/client/wenjian-executable-art-standards.md`。

## 3. 总体视觉方向

### 3.1 风格关键词

- 像素风
- 俯视角 / 2.5D 俯视
- 武侠江湖
- 山水卷轴感
- 即时动作肉鸽
- 服务端权威战斗下的清晰可读性
- 古朴但不沉重
- 少量奇幻内力表现

### 3.2 色彩基准

世界地图使用淡墨、青绿山水、纸卷暖灰和旧金点缀，强调“江湖很大”的卷轴感。

主城和小镇使用暖木色、灯笼红、青瓦灰、布幡米白，强调安全区和生活感。

野外使用墨绿、土黄、湿石灰和深林绿，强调战斗空间和危险边界。

秘境使用冷蓝、幽紫、暗金和少量血红，强调压迫感、机关和肉鸽探索。

HUD 使用宣纸底、墨线边、旧铜件、暗红血条、玉石或青白内力点缀，避免现代科幻感。

## 4. 角色视觉规格

### 4.1 比例

第一阶段玩家角色建议：

- 画布：48x48 像素。
- 实际身体高度：24-32 像素。
- 头身比：约 1:2.5 到 1:3。
- PPU：32。
- 地图瓦片：32x32 像素，1 tile = 1 Unity world unit。

普通怪物：

- 32x32 或 48x48 像素。
- 普通小怪轮廓必须比地面和草丛更清楚。

精英怪和 Boss：

- 精英怪可使用 64x64。
- 小 Boss 可使用 64x64 或 96x96。
- Boss 不应只靠尺寸变大，还要有武器、披风、轮廓和技能预警差异。

### 4.2 第一阶段职业方向

先保留四个视觉方向，不急于完整职业系统：

| 方向 | 核心辨识 | 第一阶段用途 |
|---|---|---|
| 轻剑游侠 | 细剑、轻披风、青白剑气 | 默认主角原型 |
| 重刀豪客 | 宽刀、厚肩甲、红黑刀气 | 后续重击职业参考 |
| 内功掌法宗师 | 宽袖、掌风、金白气场 | 范围技能参考 |
| 暗器身法刺客 | 短刃、飞针、深色斗篷 | 高速位移和投射物参考 |

第一阶段 Unity 灰盒原型优先使用轻剑游侠方向。

### 4.3 动画基准

| 动作 | 建议帧数 | 用途 |
|---|---:|---|
| 待机 | 4 帧 | 呼吸、衣摆、武器轻晃 |
| 移动 | 8 帧 | 8 方向移动，速度归一化 |
| 普攻 | 8 帧 | 必须明确前摇、出手帧、收招 |
| 技能 | 10-12 帧 | 可配合特效序列帧 |
| 受击 | 3 帧 | 受击闪白与轻微后仰 |
| 死亡 | 8 帧 | 第一阶段可简化 |

## 5. 场景视觉规格

### 5.1 主城 / 安全区

主城“问剑城”用于表达同服江湖的社交中心。

视觉要求：

- 城墙、城门、练武场、酒楼、铁匠铺、帮派大厅和公告区域要可读。
- 道路宽度要能容纳多名玩家同时移动。
- 安全区不需要复杂战斗空间，但需要清楚的 NPC 动线和交互点。
- 画面不要过度拥挤，避免玩家和 NPC 难以辨认。

工程影响：

- 主城可作为第一版安全区配置样例。
- 不允许 PK 的规则应来自服务端区域配置。
- Unity 侧只展示安全区提示，不决定安全区规则。

### 5.2 野外 / PK 区

“竹林古道”用于验证野外战斗空间。

视觉要求：

- 地面必须有清晰走位区域。
- 障碍物要可读，不能和背景混成一团。
- 草丛、石头、竹林和木桥用于丰富场景，但不能遮挡技能判定范围。

工程影响：

- 野外地图需要明确碰撞层和可走区域。
- 竹林和障碍物会影响服务端地图阻挡数据。
- 可视范围会影响 AOI 和 KCP 状态同步半径。

### 5.3 单人秘境

“藏剑地宫”用于验证肉鸽秘境的房间结构。

视觉要求：

- 房间和通道边界清楚。
- 机关门、宝箱、陷阱和剑碑要有可交互辨识度。
- 地面符文和光源可以增强氛围，但不能遮挡怪物和伤害范围。

工程影响：

- 秘境应先支持单人实例。
- 房间、通道、机关和宝箱后续需要进入配置表或关卡生成规则。
- 服务端决定秘境状态和奖励，客户端只表现。

## 6. 技能特效方向

### 6.1 剑气主风格

第一阶段技能以剑气为主：

- 普攻：短弧形剑光，低亮度，持续时间短。
- 直线剑气：青白主色，明确飞行方向，保留碰撞宽度可读性。
- 圆形斩击：淡金或青白范围，中心不遮挡角色。
- 残影突进：低透明度连影，避免长时间停留。

### 6.2 特效约束

- 特效不应盖住玩家和目标。
- 技能范围要比装饰光效更清楚。
- 命中特效应短促，不常驻。
- 大招可以更亮，但同屏多个特效时仍要能看清敌我。

### 6.3 对后端协议和配置的影响

技能视觉必须反向约束配置字段：

- 技能形状：扇形、圆形、矩形、飞行物。
- 范围参数：range、radius、angle、width。
- 时间参数：startupTicks、activeTicks、recoveryTicks。
- 飞行物参数：projectileSpeed、lifeTicks。
- 输入参数：aimDir、targetPoint 或 targetEntity。

第一阶段先支持直线剑气和圆形斩击，不做复杂蓄力与锁定技。

## 7. HUD 与 UI 氛围

战斗 HUD 第一阶段要求：

- 底部技能栏紧凑，不遮挡角色脚下范围。
- 左上显示 HP 和内力/怒气。
- 右上显示小地图或区域雷达。
- 调试期允许显示 serverTick、inputSeq、ping。
- 战斗核心信息优先，装饰后置。

UI 风格：

- 宣纸底。
- 墨线边。
- 旧铜件按钮。
- 暗红血条。
- 青白或玉色内力条。
- 不使用现代科幻 HUD。

## 8. Unity 第一阶段原型约束

推荐技术路线：

- Unity 当前 LTS 线。
- URP 2D Renderer。
- Tilemap。
- Pixel Perfect Camera。
- Cinemachine。
- Input System。
- Sprite flipbook 动画。

原型场景：

```text
Proto_CombatField
```

原型目标：

- 8 方向移动。
- Tilemap 场地。
- Pixel Perfect 相机。
- 普攻剑光。
- 直线剑气技能。
- 圆形斩击技能。
- 战斗 HUD。
- MockTransport 输入回放。

## 9. 暂定第一阶段参数

| 参数 | 暂定值 | 说明 |
|---|---:|---|
| 主角画布 | 48x48 px | 实际身体约 24-32 px |
| 地图瓦片 | 32x32 px | 第一阶段主规格 |
| PPU | 32 | 1 tile = 1 Unity world unit |
| 移动方向 | 8 方向 | 输入向量归一化 |
| 普攻动画 | 8 帧 | 明确出手帧 |
| 技能动画 | 10-12 帧 | 配合特效 |
| 剑光特效 | 64x64 px，8 帧 | 普攻与短范围斩击 |
| 圆形特效 | 128x128 px | 范围技能 |
| HUD 布局 | 下技能栏，左上血条，右上小地图 | 战斗可读优先 |

这些参数先作为灰盒原型基准，后续需要通过实际 Unity 场景和服务端 Tick 验证。

## 10. 质量检查标准

概念图进入 Unity 资源拆分前，需要检查：

- 是否有足够可走区域。
- 角色和怪物是否能从背景中跳出来。
- 技能范围是否清楚。
- HUD 是否遮挡战斗中心。
- 是否出现现代元素。
- 是否出现无意义文字。
- 是否适合拆为 Tilemap、Sprite、VFX 或 UI 组件。

Unity 原型完成后，需要检查：

- 16:9、16:10 和移动端比例下像素不糊。
- 8 方向移动速度归一化。
- 普攻出手帧和剑光对齐。
- 技能冷却与 HUD 遮罩一致。
- Mock 延迟下输入序号和表现校正可观察。
- 原型场景 60 FPS。
